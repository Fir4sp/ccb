Sistema CCB — Como atualizar

Versão 1.5.0 · Fase 6 (Estoques de limpeza) · 17/10/2026
Uma versão de cada vez. Esta versão precisa da 1.4.0 (CNS Limpeza) já instalada. Se ainda não rodou algum SQL anterior, rode na ordem antes deste: v1.3.0_obras.sql → v1.4.0_cns_limpeza.sql → v1.5.0_estoques.sql. O zip da 1.5.0 já traz o sistema inteiro, então não precisa subir os zips anteriores.
Arquivos
  • v1.5.0_estoques.sql: cria os saldos, as contagens e o histórico de movimentos dos DMLs (phpMyAdmin)
  • ccb_v1.5.0_atualizacao.zip: o sistema novo (por cima da pasta ccb)
  • codigo-fonte_v1.5.0.zip: só cópia de segurança, não sobe
Esta versão não traz usuários de teste novos; os da 1.4.0 servem.
1

Cópia de segurança do banco

  1. phpMyAdmin → Exportar → Executar. Guarde o arquivo.
2

Rodar o SQL

  1. phpMyAdmin → Importar → v1.5.0_estoques.sql → Importar. Deve terminar com a mensagem verde.
Se aparecer "Table 'cns_produtos' doesn't exist", falta o SQL da 1.4.0: rode o v1.4.0_cns_limpeza.sql primeiro. Se aparecer "Duplicate column name 'minimo_central'", este SQL já foi aplicado.
3

Subir o zip por cima da pasta ccb

  1. Gerenciador de Arquivos → public_html → envie ccb_v1.5.0_atualizacao.zip.
  2. Botão direito → Extrair → aqui mesmo → substituir quando perguntar. Apague o zip.

A senha do banco (config.local.php) e as fotos já enviadas não estão no zip e continuam como estão.

4

Conferir

  1. Atualize a página (no celular, feche e abra o app).
  2. Entre como Coordenação CNS → Limpeza. Deve aparecer o atalho Estoque, com o DML Central e os DMLs das casas.

Como funciona o estoque

Mudança importante na entrega do ciclo. Agora, antes de Marcar como entregue às casas, a Coordenação precisa Registrar a chegada da compra no DML Central. Se houver um ciclo já marcado como Comprado quando você atualizar, o painel vai pedir esse registro primeiro.

Cada casa tem o seu DML e o Setor tem o DML Central (galpão). O sistema guarda quanto há de cada produto em cada lugar e registra cada entrada e saída, com quem fez e o motivo. Nada é apagado, e o saldo nunca fica negativo.

  1. Chegada da compra: depois que Compras registra a compra, a Coordenação CNS confere o que chegou. A tela já vem preenchida com o que foi pedido; é só acertar o que veio diferente. O material entra no DML Central.
  2. Entrega: ao marcar a entrega, sai do Central e entra no DML de cada casa o que foi aprovado. Se faltar algo no Central, o sistema mostra o quê. Você pode lançar uma entrada (se chegou depois) ou Entregar mesmo assim: vai o que tem, na ordem dos grupos, e o que faltou fica anotado no pedido da casa.
  3. Contagem: a orientadora (nas casas dela) ou a Coordenação conta o DML com + e −. Já vem preenchido com o saldo atual, então é só mexer no que estiver diferente. A diferença aparece como consumo no histórico.
  4. Na conferência do pedido, a orientadora vê quanto a casa ainda tem de cada produto e quando foi contado. Assim fica fácil ver se o pedido faz sentido.

DML Central

  • Entrada: doação, compra avulsa ou material que chegou depois.
  • Saída: produto vencido, galão furado, uso no galpão.
  • Enviar para uma casa: envio avulso fora do ciclo (ex.: faltou para a Santa Ceia). Sai do Central e entra na casa.
  • Estoque mínimo: no Catálogo, cada produto pode ter um mínimo para o Central. Abaixo dele, a lista de estoque mostra o aviso em vermelho.

Também nesta versão

Quem é só Administrador agora vê um aviso em Obras e em Limpeza explicando que ali ele só acompanha, com o link para se dar o perfil que cria obras ou cuida da limpeza (Admin › Usuários). Foi o caso de "não tem nada para cadastrar produtos ou iniciar uma obra".

Decisões técnicas (para registro)

AssuntoDecisão
EscopoSó material de limpeza. As ferramentas ficam para depois, como combinado.
SaldoCada mudança trava o saldo daquele produto naquele DML. O saldo nunca fica negativo, garantido também pelo próprio banco.
ContagemO que foi contado vira o saldo. A diferença fica registrada como movimento de contagem, com data, para ver o consumo de cada casa.
HistóricoOs movimentos não são apagados nem editados. Um erro se corrige com um lançamento contrário ou uma nova contagem.
Testes283 testes automáticos aprovados (30 novos de estoque), fluxo completo no navegador (compra → chegada → entrega com falta → contagem → Central) e atualização feita numa cópia do banco de produção.
